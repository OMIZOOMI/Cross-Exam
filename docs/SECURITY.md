# Security and scanning policy

Updated 2026-10-01. **Local deterministic HTTP/HTML investigations are implemented. Arbitrary Chromium browsing remains disabled.**

## Current boundary and threat model

An attacker can control a target URL, DNS answers, redirect destinations, headers, response bodies, subresources, scripts, and content later shown to a model. The implemented boundary prevents this URL/DNS control from selecting forbidden destinations through `safeRequest`. It assumes trusted application code, the Node runtime, OS, network configuration, and configured DNS resolver. It is not a process sandbox or an authorization decision to crawl a website.

`@crossexam/engine/security` exports **`safeRequest(input, options)`**, a Node-only GET/HEAD primitive that performs validation, DNS resolution, connection pinning, and redirect handling together. There is no public preflight token to pass into ordinary `fetch`, no injected dispatcher/agent/resolver, and no allow-private switch. A trusted `allowRedirect(url)` callback can only restrict redirects further; it cannot select an address, change a URL, or override gate denials. Internal dependency seams exist only for deterministic tests and are not package exports. Future scanner HTTP operations must use this entry point; direct networking elsewhere would bypass the boundary and is prohibited by project policy.

`@crossexam/engine/url-policy` exports the shared, browser-safe **early** input policy. A successful result means only that the URL may undergo server-side DNS checks. The landing form uses this module locally, then submits only to the same-origin local scan API. The scanner checks the original input again and uses `safeRequest` for every target request. No public response exposes DNS decisions or peer addresses. `TargetUrlSchema` still validates domain-record syntax, including fictional fixture URLs; it is not network authorization.

## V1 URL policy

- HTTP and HTTPS only, with omitted/default ports or explicit **80/443**. Cross-scheme use of these two ports is permitted; every other port is denied. Empty/zero-padded port spellings are rejected.
- All direct IPv4/IPv6 target literals are denied, including publicly routed literals. WHATWG parsing catches decimal, octal, hexadecimal, shortened IPv4, and mapped IPv6 URL forms before the literal rule is applied.
- Reject userinfo, including empty `@`/`:@`; unsupported schemes; malformed/overlong input (2048 characters); raw whitespace, control/format characters, backslashes, and percent-encoded ASCII controls. No trimming or repair of ambiguous input. Percent escapes in the authority, empty DNS labels, underscores, trailing dots, overlong labels, and single-label names are denied.
- Normalize hostnames through WHATWG URL/IDNA, lowercase them, normalize paths/default ports, and remove fragments. Reserved/local suffixes (`localhost`, `local`, `localdomain`, `internal`, `intranet`, `lan`, `home`, `corp`, `test`, `invalid`, `example`, `onion`, `arpa`) and named metadata hosts are early denials. Unicode dot/full-width normalization cannot bypass this check. A normal-looking or IDN hostname is never trusted without DNS checks.

## Address classification

Node's strict `net.isIP` validates resolver/peer literals; pinned **ipaddr.js 2.2.0** performs IP parsing and CIDR arithmetic. Explicit ranges are a conservative superset of the [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry/) and [IPv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry/), reviewed 2026-10-01. Review these ranges when standards, cloud endpoints, or runtime/dependency versions change; they do not update themselves.

IPv4 denies unspecified/this-network space, all 127/8, RFC1918, 169.254/16, CGNAT 100.64/10, multicast, reserved/broadcast, documentation/benchmark blocks, IETF protocol assignments, AS112/AMT special ranges, deprecated 6to4 relay space, and Azure's platform address 168.63.129.16. Link-local and CGNAT rules cover common cloud/container metadata addresses.

IPv6 denies unspecified/loopback, ULA, link-local/site-local, multicast, IPv4-mapped/compatible representations, NAT64/translation, Teredo/6to4, documentation, protocol assignments, and other reserved/non-global space. V1 accepts only ordinary `2000::/3` global unicast after excluding its special-purpose ranges (including `2001::/23`, `2001:db8::/32`, `2002::/16`, `2620:4f:8000::/48`, and `3fff::/20`). Globally reachable special-purpose exceptions are deliberately denied. IPv6 scope/zone identifiers are invalid.

DNS answers matching the scanner's own globally numbered interfaces are also denied, and this is rechecked immediately before connection. This does not identify every publicly numbered service routed internally or exposed by NAT; operator network isolation remains necessary.

## DNS and rebinding guarantees

Each hop gets a new Node DNS `Resolver`. A and AAAA queries run together against the absolute DNS name, using the configured DNS servers rather than a later OS hostname lookup. Both completed answer sets are inspected before connecting. One unsafe, malformed, family-mismatched, or local-interface answer rejects the whole destination. Empty combined results and more than 32 answers fail closed. Only `ENODATA` means an absent family; NXDOMAIN, timeout, SERVFAIL, refusal, cancellation, and other failures reject even if the other family returned a public address. DNS queries are cancelled on abort/deadline and resolver disposal. CNAME processing is performed by DNS resolution; the terminal returned addresses are what matter for connection policy.

The first address in the validated set (A before AAAA; IPv6-only is supported) is pinned for exactly one HTTP operation. There is no address fallback, persistent cache, retry, socket reuse, or TTL-based authorization. Availability is intentionally conservative. Every redirect, including another path on the same hostname, obtains a fresh complete resolution.

A fresh explicit HTTP(S) Agent has environment proxy configuration disabled. Its private connection function supplies the validated **literal IP**, address family, and approved port directly to `net.createConnection` or `tls.connect`; family auto-selection is off. No second DNS lookup occurs at connection time. The canonical hostname supplies Host and TLS SNI, and normal trusted-certificate and hostname checks remain mandatory. The Agent hands the socket to HTTP only after connect/secureConnect verifies the exact peer address and port, and HTTPS authorization. No HTTP request bytes are written before those checks. The one-use socket and Agent are destroyed on success, failure, or cancellation. This uses documented [Node Agent connection hooks](https://nodejs.org/docs/latest-v24.x/api/http.html#agentcreateconnectionoptions-callback) and explicit isolation from [Node environment proxy behavior](https://nodejs.org/docs/latest-v24.x/api/http.html#built-in-proxy-support).

**There is no DNS validation/connection TOCTOU gap in this HTTP primitive.** A DNS change after validation cannot change its literal socket destination. This does not prevent kernel/network routing, DNAT, a deployment-specific translation prefix, VPNs, or a remote public proxy from forwarding traffic elsewhere. The trusted resolver's own control-plane traffic is outside the target-address policy. Use a worker without internal reachability or credentials; do not treat this library as an OS firewall.

## Redirects, bounds, and result model

Only 301/302/303/307/308 are followed, manually. Location is checked before parser normalization can erase credentials/authority ambiguity. Absolute, scheme-relative, and relative locations receive the complete target policy; new hosts and same-host paths are re-resolved. HTTPS-to-HTTP downgrade is denied. Fragment-normalized loops are detected; at most **5 redirects / 6 connections** are possible, and callers may lower the limit. Missing, malformed, duplicate, or overlong locations fail closed. Redirect bodies are discarded immediately. Other statuses are returned as responses, not followed.

Only GET/HEAD are accepted. Caller-supplied cookies, authorization, headers, bodies, agents, lookup functions, TLS overrides, and proxies are not API options. The primitive sends a fixed User-Agent, correct Host, `Accept-Encoding: identity`, and `Connection: close`. It rejects compressed responses rather than decompressing unbounded content; upgrades are denied. Default whole-operation deadline is **10 seconds**, hard ceiling **30 seconds**. Final response body ceiling is **1 MiB**; each header block is limited to **16 KiB**, with at most 100 response header fields. Redirect bodies do not accumulate. Deadline/cancellation cover DNS, connection, TLS, headers, body, and redirects. These per-request safeguards compose with the bounded HTTP collector described below.

Results are discriminated unions. Success contains final URL/status/headers/body and a hop history. Failure contains a stable reason, blocked stage, hop, optional address classification, and completed history. Reasons cover input/protocol/credentials/port/hostname/IP policy, DNS failure or unsafe answers, redirects/loops/limits, TLS/network failure, peer mismatch, response limits, timeout, and cancellation. A denied redirected destination has `UNSAFE_REDIRECT` plus its internal cause. Exception messages and resolver infrastructure details are not returned. TLS/parser errors are reduced to `REQUEST_FAILED` unless a more specific boundary reason exists.

These records are **internal**: URL queries, response headers/body, and public peer addresses can be sensitive. The collector never persists the raw transport result or history. It retains a compact whitelist of response/document facts, removes reference queries/fragments, and excludes cookies, authorization headers, raw HTML and peer addresses. Future adapters must preserve this separation. The current UI displays “This destination cannot be scanned.” without reason codes or resolved addresses.

## Current deterministic HTTP collector

`apps/scanner/src/limits.ts` centralizes limits: 8 page attempts, depth 2, concurrency 1, 10 safe-request operations (pages plus two conventional metadata endpoints), 8 seconds per operation, 45 seconds per scan, 1 MiB per page and 256 KiB per metadata response. Lower caller page/deadline limits are honored. Redirects retain the gate's five-hop ceiling, so at most 60 socket connections are possible. Completed response bodies sum to at most 8.5 MiB; `receivedBytes` counts completed response bodies, not total wire traffic, headers, discarded redirects, or rejected body chunks. No retries. Parser input, element count (30,000), discovery candidates (100), reference lists (40), text (500 characters), robots rules (200), and sitemap hints (50) are bounded. Retained reports are capped separately at 4 MiB.

The initial redirect chain may select a different public origin after all gate and crawl checks. Only the final origin (scheme, hostname, effective port) is eligible for further document navigation: no sibling subdomains or third-party crawling. Query targets, fragment-only links, downloads, non-document extensions, forms, API/auth/account routes and obvious action paths are skipped. Percent-encoded/nested ambiguous action paths are rejected. This is a secondary conservative GET guard, not a guarantee against side effects from an arbitrary public server.

`allowRedirect` executes after the gate's URL/downgrade policy and before the next DNS query/connection. Only literal `true` allows continuation; denial, throw, or asynchronous return fails closed. Every allowed redirect still undergoes complete DNS/IP/peer/TLS validation. Discovered-page redirects must pass the final-origin, navigation and robots policy. Metadata redirects retain their original origin and exact path. The hook is trusted application code and never exposed as a request-body option.

The collector attempts conventional `/robots.txt` and `/sitemap.xml` through `safeRequest`. Initial entry HTML is collected before robots determines subsequent discovery. Missing robots (404/410) permits bounded discovery; errors, unsupported metadata or excessive rules stop further pages conservatively. Relevant wildcard/CrossExam disallows use conservative prefixes; wildcard/end-anchor rules may overblock and Allow exceptions do not relax them. Sitemap XML is capped, rejects DTD/entity declarations, and never recursively loads indexes or declared remote sitemaps. HTML meta nofollow is honored. Robots is not authorization or a complete standards-compliant crawler engine.

Cheerio's slim HTML/XML parser operates only on returned bytes. No `fromURL`, browser, script execution, external entity loading, resource fetching, form submission, authentication or AI calls. HTTP charset declarations are honored; otherwise UTF-8 is assumed. Forgiving HTML parsing does not establish browser DOM behavior. Resource observations cover explicit src/href declarations and font preloads, not CSS imports, srcset expansion, or runtime resources. Missing security headers are informational observations, never vulnerability findings.

## Local execution, storage and public output

The Node route `POST /api/scans` requires JSON, a loopback application hostname, exact Origin matching an allowlisted original Host (Next normalizes loopback request URLs), and no cross-site Fetch Metadata. It bounds input to 4 KiB/5 seconds, allows one active scan per process and six starts per minute, and connects client cancellation to the collector. These are local admission controls, not distributed rate limiting or authentication. The application remains bound to loopback by its development/production preview commands; do not deploy this adapter as a public service.

Reports are runtime-validated, assigned random UUIDs, written atomically with restrictive file permissions, and read only through validated IDs. No arbitrary filesystem paths or public report listing. Keep at most 20 reports, expire reads after 24 hours, prune on subsequent saves. Files live under the web process's ignored `.crossexam/reports` directory. IDs are not access control. Public page metadata can itself contain personal/sensitive text; only compact required fields are collected, not full HTML, form values or cookies. React renders all target strings as text; no target HTML, remote image, or executable markup is embedded in the UI.

Failed/partial observations produce honest generic messages or partial reports. Deterministic reports cannot contain simulated evidence, AI runs or invented challenge/experiment records. Confirmation means a rule matches the recorded fact, not reproduction, exploitability, accessibility compliance or browser performance. No LCP/CLS, console failures, runtime JavaScript failures or full waterfall are fabricated.

## Browser boundary research (2026-10-01, before implementation)

Primary references: [Chromium proxy specification](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md), [Playwright networking](https://playwright.dev/docs/network), [context routing/WebSocket API](https://playwright.dev/docs/api/class-browsercontext), and [Playwright container guidance](https://playwright.dev/docs/docker). Installed Playwright is 1.63.0. Documentation is a design input, not proof of this machine's browser behavior; controlled execution results will be recorded separately.

- Manual HTTP proxy settings cover HTTP, HTTPS via CONNECT, and WebSockets. Chromium delegates target DNS to an HTTP proxy. Use one explicit proxy, never PAC/WPAD or a DIRECT fallback. IPv4/IPv6 literal URLs still require policy checks.
- Chromium implicitly bypasses proxies for localhost names, 127/8, ::1 and IPv4/IPv6 link-local literals. The subtractive manual bypass rule `<-loopback>` removes these defaults; an empty bypass list does not. Test a loopback sentinel rather than merely trusting flags.
- Context routes can restrict page/frame/resource methods and budgets. They neither pin TCP peers nor isolate subprocesses, and service workers can hide requests. Block service workers; install separate WebSocket routing before creating pages. HTTPS redirects/new authorities cause new proxy decisions, but encrypted paths, methods and WSS upgrades within an approved CONNECT stream are not visible to a non-MITM proxy.
- CONNECT must validate all DNS answers, dial one literal, verify the peer before acknowledging, and bound tunnel lifetime/bytes. Browser TLS validation stays enabled end-to-end; no local CA or TLS interception. Pinning prevents rebinding that connection, not public-server forwarding.
- Proxy flags do not isolate UDP, WebRTC/STUN/TURN, QUIC/WebTransport, browser services, or compromised subprocesses. Disable/bound capabilities as defense in depth; only external process/network enforcement closes alternate paths. Ordinary pages lack unrestricted raw TCP APIs; this does not make proxy configuration a firewall.
- This macOS workspace has no Docker or Podman executable. Do not install a privileged host firewall or claim untested container isolation. Implement a fail-closed isolation interface and fixture-only worker harness; arbitrary launches remain disabled pending verified OS-level enforcement for all worker subprocesses, TCP/UDP/IPv6, filesystem and resource budgets.

## Implemented proxy and fixture-only Chromium worker

`@crossexam/engine/browser-egress` exposes `startEgressProxy()` with fixed production dependencies. It binds an ephemeral IPv4 loopback listener, provides bounded structured decision records, and closes idempotently. The internal dependency seam is not a package export. Tests alone substitute a closed resolver and in-memory HTTP responses/local TLS sockets; there is no production allow-private option or second IP range list.

HTTP absolute-form requests permit GET/HEAD without bodies. Existing `validateTargetUrl`, `resolveHost`, `validateAnswers` and `requestPinned` enforce all-answer DNS validation, current local-interface denial, literal pinning, peer verification and no fallback. Request cookies/Authorization are not forwarded. Hop-by-hop/connection-nominated response headers and Set-Cookie are removed. The proxy does not follow redirects: it validates the Location URL and all DNS answers before returning it, and independently resolves/pins the subsequent browser request. Redirect loops are bounded by overall request/lifetime caps (not the deterministic scanner's five-hop counter).

CONNECT permits only strict hostname:443 authorities, never IP literals, paths, userinfo, ambiguous ports or nested proxy targets. Shared DNS policy validates every answer; `connectPinned` dials one literal TCP address and checks the peer before 200 or buffered tunnel bytes are released. No MITM, certificate substitution or TLS error suppression occurs. Chromium validates certificates; the proxy cannot inspect the encrypted TLS session's SNI, URL, method, headers, redirects or WSS upgrades. An approved tunnel can carry multiple requests without new DNS checks, but its destination cannot rebind. A new CONNECT is always checked again. Cleartext upgrades are denied. Worker WebSocket routing separately denies WS/WSS before pages are created.

Proxy limits: 60 seconds lifetime, 10 seconds per HTTP operation/CONNECT tunnel, 1 MiB per completed HTTP body, 16 MiB cumulative delivered HTTP body plus tunnel bytes in both directions, 64 requests/CONNECTs, 16 simultaneous accepted client sockets, 96 total client sockets, 128 retained audit records, 16 KiB HTTP headers. These are application budgets, not wire-traffic, memory or process quotas; response buffering and discarded/denied traffic are not counted as delivered body bytes. Audit records contain only decision, request type, reason code and classification—no host, URL, query, headers, cookies, payload or raw error. Ring truncation intentionally limits retention.

`apps/browser-worker/src/fixture-worker.ts` is an internal, non-exported test harness. It launches fresh sandbox-enabled Chromium with a fixed loopback proxy, `<-loopback>`, no DIRECT/PAC fallback, blocked browser DNS resolution, QUIC disabled and non-proxied WebRTC UDP disabled. A minimal environment excludes inherited secrets/proxies. A nonpersistent context has no storage state/credentials, TLS checks enabled, service workers blocked, no granted permissions and downloads disabled. Context routes restrict methods, types and 64-request workload, and extra pages are closed. Job timeout is 1–30 seconds, with early cleanup reserve; cleanup is cooperative, not an external process kill guarantee. No file chooser is granted and no user profile is reused, but this fixture launcher alone does not establish host filesystem/process isolation; the separately verified Linux backend supplies that outer boundary.

### Task 10A: active enforcement, then probe release

The former implementation waited for `systemd-run --pipe --wait` to finish before reading service limits. A successful short-lived transient unit can already be unloaded at that point; `systemctl show` may return default-looking values with exit status zero. The baseline CI failure reported `MemoryMax=infinity`, `TasksMax=19151`, `CPUQuotaPerSecUSec=infinity` and an empty ControlGroup. Those values cannot prove whether the completed service was constrained.

The launcher now starts with stdin held open and empty. The fixed probe already reads through stdin EOF before dispatching its operation, so this is a startup barrier. A bounded active-state query requires `LoadState=loaded`, `ActiveState=active`, a positive MainPID, a nonempty unit-specific ControlGroup, and a nonzero InvocationID. `linux-cgroup.ts` validates the observed path before reading only fixed, bounded kernel files under `/sys/fs/cgroup`; traversal, symlinked paths, missing files and malformed values fail closed. It requires `memory.max=1073741824`, `memory.swap.max=0`, `pids.max=128`, finite positive `cpu.max` quota equal to period (one CPU), and MainPID membership in `cgroup.procs`. Systemd's configured properties are checked as additional evidence, never a substitute for kernel values.

The same active PID/cgroup/invocation is confirmed again after these reads. Only then is JSON written and stdin closed. Terminal properties are outcome diagnostics, not limit evidence: a normally unloaded successful unit is allowed only after the active proof; a retained failed unit must match the captured invocation. Bounded startup/query/launcher timeouts and verification failures enter unit kill/stop cleanup. Cleanup uses the actual captured ControlGroup, never an invented `/system.slice` path. It requires inactive service state and an absent captured cgroup or `cgroup.events` reporting `populated 0` (including descendants). If no valid path was captured, cleanup is attempted but not claimed as proven. Each completed probe logs its active properties/kernel values before subsequent probe assertions can fail.

Task 10A establishes a fixed probe's active resource configuration, not protection against a privileged host administrator changing cgroups. Task 10D-C subsequently completed the controlled Linux acceptance gate (run 37196847138); public launch and production deployment remain separate.

Cleanup passes only when the final service state is not active and the actual cgroup captured during active verification is absent or reports `cgroup.events` `populated 0`. A populated cgroup, active state, malformed captured path, permission/read failure or timeout fails closed.

No host capabilities are acquired. Flags unconfined do not add filesystem mediation; filesystem/network confinement comes from the unchanged outer layers. AppArmor attachment is pathname-based, not a cryptographic global binary identity; sealed-root validation and trusted host/mount provisioning supply artifact linkage. A hostile privileged host could replace policy or mount another artifact at that path and remains outside the threat model. Linux kernel vulnerabilities, complete production hardening and broader deployment validation remain risks. No public browsing is enabled by this policy.

## OS/network isolation — controlled acceptance passed; public launches fail closed

`@crossexam/browser-worker` exports only the unavailable public launcher and immutable isolation status; `launchBrowserWorker()` always throws `ISOLATION_UNAVAILABLE`. No caller flag, environment variable or status object can enable arbitrary browsing. The normal form/API still imports only the deterministic HTTP scanner. Task 9a's controlled Linux isolation gate is complete; this does not authorize arbitrary browsing or constitute a production deployment audit.

The Linux backend above supplies this boundary only when its runtime assumptions are present and its adversarial harness passes. Browser subprocesses, compromised browser code, alternative UDP/TCP mechanisms, host filesystem access after compromise, deployment NAT/translation and public forwarding services remain outside the application proxy guarantee. ### Remaining prerequisites

An approved initial URL does not constrain scripts, redirects, images, iframes, workers, popups, third-party resources, WebSockets, service workers, downloads, WebRTC, or browser-internal networking. Chromium does not use this Node Agent. Never pass a successful early-policy result to `page.goto` or assume a prior `safeRequest` approves a later browser connection.

Playwright context routing is useful for allowed methods, scope, resource/request limits, and aborting known unwanted traffic. It does not bind Chromium's DNS/connection to a prior check. [Context routing has service-worker limitations](https://playwright.dev/docs/api/class-browsercontext#browser-context-route), and [updated service-worker main scripts have documented routing limitations](https://playwright.dev/docs/service-workers#known-limitations). WebSocket routing is a separate API and must be installed before connections. Interception is defense in depth, not the network boundary.

Required before arbitrary browser scanning:

1. Run Chromium in a disposable, unprivileged worker/container/network namespace with no credentials, host mounts, privileged flags, or access to local/control-plane services. A fresh browser context alone is insufficient isolation.
2. An OS/container firewall permits only a designated enforcing egress proxy plus strictly controlled DNS/control channels. Deny all other TCP/UDP egress, including direct IPs, IPv6 bypass, QUIC, and WebRTC. DNS must not become an unrestricted alternative channel.
3. The proxy validates the destination and pins connections for every HTTP request and HTTPS CONNECT tunnel using the same policy. No unrestricted proxy chaining. Explicitly disable/bound proxy bypass and test it: [Chromium has implicit localhost/link-local bypass rules](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md). Browser flags alone are not sufficient enforcement.
4. Block service workers, downloads, unsupported protocols, and WebSockets until explicit enforced policies exist. Install context-level request policies before opening pages; restrict same-origin crawl, approved GET/HEAD observations, and separately approved third-party reads.
5. Test adversarial initial pages and resources, redirects, workers, popups, WebSockets, DNS rebinding, direct TCP/UDP/IPv6, and proxy bypass in a controlled network. Confirm denied traffic at the network boundary, not only Playwright events. Add job-wide budgets and guaranteed cleanup/cancellation.

The proxy and fixture worker are implemented and tested; the Linux outer confinement and internal Chromium sandbox passed complete controlled resource/cleanup acceptance. Stage 11 adds a collector for owned fixtures only. Public browser admission and production deployment remain unimplemented. The local HTTP collector and live report UI do not provide these browser guarantees. Browser scanning is **not production-safe** today.

### Stage 11 collection and privacy

The internal collector permits only fixed owned fixture identifiers. It inherits GET/HEAD-only routing, websocket denial, no DIRECT fallback, blocked service workers/downloads, fresh state, Chromium sandbox, proxy DNS/IP validation and the unchanged worker deadline (default 10 s, allowed 1–30 s, cleanup reserve up to 1 s). Linux's independent service deadline remains 45 s. The collector observes one page; it never submits forms, clicks, recursively crawls, requests bodies through Playwright, captures screenshots, reads browser storage or interprets vulnerabilities/performance/accessibility.

Retention limits live in the versioned contract: 64 requests, 32 responses, 32 warnings/errors, 16 page errors, five retained redirect relationships (six navigation entries), 20 headings, 40 links, 10 forms, 40 declared resources, 20 input-type buckets per form and at most 10,000 inspected DOM elements. Text/header values are 256 characters, sanitized URLs 1,024 characters, nine explicit response header names, final JSON 32 KiB. Oversized URLs are omitted, never truncated into another destination. Lists retain event/document order and evict tails; every loss has a dimension count or explicit string/URL/header/DOM/result-size marker. DOM counts cover only inspected elements, not an unbounded whole document. Redirect retention is not new traffic permission: proxy/worker limits and the existing deadline remain authoritative.

The DOM extraction bounds fields inside the renderer before IPC and reads form methods/actions/input types and counts only, never names/values. Network collection reads method/type/URL/outcome/redirect identity, never request headers or payloads. Response headers use a strict schema allowlist: content-type, CSP, HSTS, x-content-type-options, referrer-policy, permissions-policy, x-frame-options, cache-control and server. Cookie/authorization/custom headers cannot enter the output. [Playwright's cached response headers](https://playwright.dev/docs/api/class-response#response-headers) can omit security-related fields; missing fields mean not retained/observed, not proof of absence or vulnerability. No allHeaders/body API is used.

URL retention removes userinfo, every query/fragment and likely credential-bearing/opaque long path segments. Bounded free text removes controls, recognizable labelled credentials, bearer/basic credentials, JWTs, emails and CSP nonces. This is not complete DLP: arbitrary unlabelled secrets or personal data in hostile page text cannot be identified reliably. Owned fixtures use disposable markers, not usable credentials. This limitation requires separate privacy/admission review before public collection. Raw stacks, console arguments, browser profiles, cookies, auth headers, bodies, input values, storage and binary assets are not collection fields.

Observation window: navigation load followed by 300 ms of bounded runtime collection, then selected DOM extraction. These wall-clock timings are collection durations, not LCP/FCP/TTFB, readiness guarantees or performance scores. Events after closure are outside coverage; unfinished requests remain `observed`, not falsely marked successful. Navigation failure, worker deadline, cancellation, crash and proxy failure retain partial observations and use existing worker cleanup. The Linux harness additionally verifies cgroup removal and sentinel isolation; public admission remains DISABLED.

## Workload, evidence, and AI policy

Do not submit forms, log in, upload, click action controls, or mutate a site. Even GET may have side effects; a destination being public is not authorization to invoke destructive routes. Robots/rate limits inform crawling, not authorization. The current HTTP collector is limited to 8 page attempts, depth 2, sequential requests and a 45-second ceiling. Stage 11 browser collection retains the controlled worker/proxy budgets described above; public admission and deployment quotas remain future work.

Escape captured content; never render target HTML directly. Redact query secrets, cookies, auth headers, and personal data. Do not let website text override role policy or invoke tools. Runtime-validate provider results and evidence references. Public passive technical observations only; no exploitation, brute force, credential attacks, or offensive scanning.

The latter creates its own ephemeral loopback server and uses a test-only routing shim; it never contacts real public sites, live DNS, metadata services, or existing private infrastructure.
