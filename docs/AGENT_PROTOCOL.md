# Agent protocol

## Stage 16A offline Reproducer planning and authorization

`createReproducerSession(report, fakeConfiguration, {skepticReview?, existingRun?})` produces a separate immutable `ReproducerRun` v1. ScanReport v2, its top-level experiments, the two-role TribunalRun v1, SkepticReview v1, evidence, Findings and verdicts remain unchanged. There is no real provider, fixture operation, browser launch, filesystem/storage subsystem or public admission. CrossExam remains free for all users. Stage 14C's owner-deferred paid acceptance remains pending and unchanged.

Admission reuses existing offline Skeptic parent/replay validation without a role invocation. It requires a schema-valid fixture report and coherent finalized Explorer/Breaker parent; accepted records require response hashes and timestamps inside their role audits. An optional SkepticReview must match the exact report, current policy/request hashes, references and same-claim context links. Unsafe parent text, missing/omitted cited evidence, mixed identity and external/mismatching replay fail before either injected component. Failed/aborted parents, no accepted claims, no challenge, or an optional failed/aborted/ineligible review skip with zero calls. A partial Tribunal with failed Breaker can use an accepted matching Skeptic challenge. Fixture source is trusted host metadata, not proof of ownership.

The immutable view reuses numeric/presence-only catalog bounds: 256 inspected candidates, 96 digests, 4 KiB each and 96 KiB catalog. It supplies only available parent-authorized OBSERVED/DERIVED evidence, accepted Explorer claims, Breaker/Skeptic challenge projections, upstream statuses, fixed limitations and host operation IDs. Skeptic related Breaker links are context, never evidence or authority. Findings, verdicts, experiments, generic Evidence.data, website text, URLs, network identifiers, DOM/HTML/axe snippets and sensitive payloads never cross this boundary. Accepted upstream model text uses the existing conservative privacy guard and stays structured untrusted data without instruction/tool authority; this guard is not universal secret detection.

Strict ReproducerProposal v1 contains only schemaVersion and plans, with zero or one plan. A plan contains only claimId, challengeId, operationId and one to six unique evidenceIds. It requires an accepted parent Explorer claim, a same-claim accepted Breaker or matching Skeptic challenge, and available authorized projected evidence. Unknown authority fields, URLs, paths, methods, headers, scripts, selectors, targets, timeouts and arbitrary parameters fail structural validation. Unknown operation IDs or invalid references/privacy fail semantic validation. The fixed interface registry contains only fixture-document-repeat-v1 in injected-fake mode, with parametersAllowed=false; there is **no implementation** of that operation.

Exact planning semantics: valid empty is completed, one call, non-null request/response hashes, zero accepted/rejected plans and no authorization/execution. One valid plan is completed with one host-owned INFERRED plan. One semantically invalid plan is no-valid-output with exactly one known rejection and no authorization. Multiple plans or malformed JSON are whole-response schema-failure, never prefix acceptance; oversized output is limit-exceeded. partial-rejection is forbidden in Reproducer planning/execution statuses; existing upstream statuses remain unchanged. These states imply no agreement, truth, safety, reproduction or verdict.

The host assigns run/session/plan/audit IDs and times. `run.parent.snapshotHash` is exactly the shared Skeptic admission's SHA-256 of the normalized, schema-validated report, independent of the optional review. `skepticReviewId` and `skepticReviewHash` are both null without a review; otherwise they identify the matching admitted immutable review and the SHA-256 of its existing deterministic JSON serialization. Matching admission succeeds before hashing or authorization. Authorization metadata's `parentSnapshotHash` equals the report hash, and its required nullable `parentSkepticReviewHash` equals the separate review hash. The private one-use grant's `bindingHash` is the composite identity over both parent hashes, run/session/plan IDs, canonical plan hash and operation-policy hash. The corrected binding semantics are included in the Reproducer policy hash; no report/Tribunal/Skeptic schema migration is needed.

The grant is consumed synchronously immediately before the fake executor attempt; wrong binding or second consumption fails. Replay continues to bind the complete parent, request, schema/policy identity and configured fake provider/model: changing the report, changing only the review, or adding/removing a review invalidates replay. Matching replay returns only the original immutable in-process run without redispatch; serialized/cloned runs remain ineligible. The executor receives an opaque in-process host-resolved operation capability, never a proposal, report, target or parameters. It can inspect only the fixed interface descriptor. No capability enters a view or artifact; only bounded hashes/identity/issued-and-consumed metadata are recorded. This is not a remotely usable token or authenticated storage receipt.

Limits: one planner call, requested 768 output tokens, zero retries, 20 seconds; one fake executor attempt, 5 seconds; whole-session acceptance 25 seconds. Complete request <=128 KiB, complete untrusted planner envelope <=24 KiB before parsing, fake executor envelope <=1 KiB, finalized run <=32 KiB. Object handling rejects getters/toJSON, cycles, exotic values and excessive nesting/cardinality. Audits retain schema/policy/request/response hashes, actual timing, bounded reported usage or null, counts and stable codes; no raw output/errors/reasoning. These bounds do not increase browser worker deadlines or cgroups.

Only strict test-only FAKE_COMPLETED output with SIMULATED provenance can be accepted; it creates no observation and establishes no reproduction. Consumed authorization without validated final fake output is outcome-unknown, including failure, invalid output, timeout and abort. Unknown/failed output has no result. Timers/listeners are removed, component abort signals triggered, and late resolution cannot mutate finalized runs. Repeated/concurrent session calls share one promise; the first caller owns cancellation.

Matching replay accepts **only the original frozen finalized object issued by this process**, bound to the same report/review/request/policy/configuration identity, returning that exact result or unknown state without calls. Serialized/cloned/external artifacts, including incomplete artifacts, fail closed without re-execution. After crash/restart there is no recoverable run, capability or replay guarantee. The guarantee is **at most one trusted-host executor attempt per capability object within one process**, not durable/distributed/external at-most-once execution. A new session without the original object is a new fake session, not crash recovery. Injected functions are trusted host code, not sandboxed: abort stops acceptance, not arbitrary JavaScript ignoring abort or blocking the event loop. Fakes prove no actual browser/process operation or resource cleanup.

Later controlled-fixture execution requires separately reviewed host target admission, an actual fixed non-destructive operation using the accepted isolation/proxy/lifecycle, and observed-result validation/provenance. Stage 16A SIMULATED completion cannot serve as evidence of a real repeat.

## Stage 15 offline Skeptic review

`createSkepticSession(report, fakeProviderConfiguration, existingReview?)` returns a separate immutable `SkepticReview` v1. It does not add a third role to TribunalRun v1, change ScanReport v2 or canonical Challenge, append report arrays, or enter Stage 14C's two-call release/checkpoint path. The owner explicitly deferred paid acceptance: Stage 14C remains **offline implemented, real-provider acceptance pending**.

Admission requires a schema-validated fixture-source report and one finalized Explorer/Breaker overlay with coherent scan identities, audit timing and host status derivation. Completed/partial parents with accepted Explorer claims are eligible, including failed/empty Breaker output; both upstream audit statuses remain visible. Failed/aborted parents or no accepted claims skip with zero calls. Live source, missing parent, mixed identity, unsafe upstream text, unavailable cited evidence and mismatched replay fail before invocation. Fixture source is trusted host metadata, not proof that a caller actually owns a website; this API has no public admission route.

The allowlisted Skeptic request contains fixed role/instructions/data trust/limitations, collection layers, existing numeric/presence evidence digests, accepted Explorer claim and Breaker challenge projections, upstream statuses and omitted-evidence count. No generic report, Findings, Evidence.data or website text is exported. Accepted model text is rechecked with the unchanged shared privacy guard; retained strings remain untrusted data without instruction/tool authority. Catalog bounds remain 256 examined / 96 digests / 4 KiB per digest / 96 KiB catalog. Only parent-authorized OBSERVED/DERIVED evidence is supplied. An omitted cited digest rejects admission instead of silently weakening support. Complete request validation enforces 128 KiB; an oversized view is rejected.

Strict SkepticProposal v1 contains up to six challenges, two per claim. Each has accepted parent Explorer claim ID, existing challenge category, question <=480 characters, up to six supplied evidence IDs, up to three same-claim parent Breaker links, and conditional missingEvidence <=320 characters. Breaker links are context, never evidence. Only missing-evidence may omit evidence references, requiring a nonempty missingEvidence description. Unknown fields/authority, malformed structure and cardinality violations reject the entire response. Invalid references, unsafe text and duplicate meanings reject individual items, retaining valid siblings with partial-rejection status. NFKC/whitespace/case-normalized meaning and sorted evidence IDs reuse Breaker's deduplication; related links cannot evade it. Host IDs, scan linkage, timestamps, Skeptic attribution, INFERRED provenance and open status are assigned only after validation. Related links are stored beside, not inside, strict canonical Challenges. Validation means admissibility, not truth, resolution or a verdict.

One trusted injected fake call, zero retries, requested 1,024-output-token cap and a separate 20-second acceptance deadline. The complete fake envelope is limited to 24 KiB before parsing; object serialization also rejects getters, toJSON, cycles, exotic objects and excessive nesting/cardinality. A dedicated audit retains configured fake labels, injected-fake mode, schema/policy versions and hashes, request/response hashes, real timestamps/monotonic elapsed time, categorized status, bounded adapter-reported usage or null, accepted IDs, rejection counts/knownness and bounded codes. Raw output, exceptions, reasoning and secrets are not retained. A structurally valid response with challenges: [] completes with zero challenges, one call, non-null request/response hashes, zero rejections, empty rejection codes and rejectedCountKnown: true. no-valid-output is reserved for one or more proposed items all rejected by host semantic/reference/privacy validation: one call, a non-null response hash, zero accepted records, a positive known rejection count and at least one rejection code. Neither status implies agreement, safety, truth or a verdict. Matching reviews of either state replay without another call. Review output is schema-validated and capped at 64 KiB.

The review binds SHA-256 of the exact schema-normalized parent snapshot with recursively sorted object keys (array order retained), scan/run identity, parent authorized evidence IDs, reviewed claims and reviewed Breaker challenges. Replay revalidates schema, binding, policy/request identity, audit consistency, references, same-claim links, privacy, ID collisions and duplicate meaning, then returns the original immutable records/audit with no call. Repeated session runs share one promise; the first caller owns cancellation. Late results cannot authorize state, listeners/timers are removed, and the adapter receives an abort signal. This is **offline snapshot replay**, not authenticated storage, paid-call idempotency or distributed recovery. An injected adapter is trusted in-process host code, not sandboxed: ignoring abort or blocking the event loop may continue work/delay settlement, but results after the deadline are not accepted; elapsed time is never fabricated/clamped. No SDK/controlled-provider imports, credential lookup, storage subsystem, network dispatch, external wire profile, tools or public route are added.

Breaker receives just accepted claim proposal content plus host ID/INFERRED attribution. Separate strict wire schemas normalize only `missingEvidence:null` to absence; original host validation follows.

A trusted host pre-dispatch hook durably consumes one release/role slot and issues a one-use exact-body authorization. A finalized-role checkpoint hook persists actual canonical records/audit before the next role. Neither hook is passed to a provider/model. Optional profile/reasoning/receipt/reasoning-token audit fields preserve old fake reports. Provider failures additionally distinguish quota/rate/refusal/incomplete/limit; raw errors and reasoning remain excluded. Public/live admission and paid acceptance remain disabled/unverified.

## Stage 14B: proposals cross a host trust boundary

```text
Collected Evidence → provider-safe digest → Explorer proposal
  → host validation → canonical Claim → Breaker proposal
  → host validation → canonical Challenge
```

Models and website content are untrusted. The host alone assigns IDs, scan linkage, timestamps, attribution, provenance, status, budgets and authorized references. Models cannot create evidence, canonical records, findings, experiments or verdicts. Stage 14B implements only Explorer and Breaker with injected deterministic fake adapters. There is no provider SDK, model network request, framework, agent tool or public submission integration.

`@crossexam/agents` exposes `createTribunalSession(report, { Explorer, Breaker })`. Its validated report snapshot and returned report are deeply frozen. `session.run({signal})` performs at most one call per role, sequentially, and publishes a complete validated overlay. Concurrent/repeated calls reuse the same promise and IDs; a persisted report containing an overlay is returned without new calls. This is snapshot-level idempotency, not distributed request deduplication or an authenticated persistence/admission API. The first call owns cancellation.

## Proposal v1

Strict Zod schemas reject unknown fields at every proposal level. Explorer returns at most five evidence-backed claims with statement, scope observation/conditions/limitations, falsifier and up to six unique evidence IDs. Bounds are 480/160/320 characters, four conditions and six limitations. Breaker returns at most eight challenges, three per accepted Explorer claim, with category, question, evidence IDs and conditional missingEvidence. Only missing-evidence may have no references; that case requires a nonempty description. Other categories prohibit missingEvidence and require a reference. The eight category names are fixed in `contracts/src/tribunal.ts`.

The host rejects unknown/fabricated/excluded references. Breaker cannot challenge deterministic base claims or another scan/session's claims. Structure failure rejects the entire response; semantic reference/privacy/duplicate failures reject individual proposals and mark partial-rejection. Canonical claims/challenges are INFERRED and attributed to Explorer/Breaker. Existing OBSERVED/DERIVED evidence never changes. Case/whitespace/Unicode-normalized statement plus sorted references deduplicate claims, including existing deterministic claims. Challenges deduplicate claim/category/question/references/missingEvidence. Hard cardinality caps also bound distinct paraphrases.

## Provider export v1

`evidence-digest.ts` is a separate allowlisted projection, not a generic serialization of Evidence.data. Only known code/collector pairs with OBSERVED or DERIVED provenance qualify. SIMULATED, INFERRED, unknown collectors and unprojectable records are excluded and counted. At most 256 candidate records are examined and 96 digests retained in input order. Each digest is <=4 KiB; the catalog reserves 32 KiB of the <=128 KiB complete request/view budget for the envelope and accepted claims.

V1 deliberately exports **no website text or URL string**. Titles/details are host-authored code labels; facts are code-specific numbers, booleans or explicit null. Header values become presence booleans. Browser JSON observations are size-checked, parsed and projected by code; console/error text, DOM attributes, axe data, URLs, bodies and generic nested objects are never copied. Location is protocol plus a document ordinal; host/path/query/fragment/userinfo and network addresses are absent. The ordinal associates observations of the same origin/path, ignoring query/fragment, but cannot locate/reproduce a page on its own. Host-owned scan/evidence IDs and captured time remain available. Completeness records omissions and available collection truncation; unknown completeness is null.

Explorer receives collection layers, fixed limitations and the evidence catalog, with no deterministic Findings or claims. Breaker receives the same catalog and only accepted canonical Explorer claims. Requests separate fixed instructions from structured untrusted data. Retained provider-generated text remains inert data with no tool authority; a conservative secondary guard rejects URL/IP/path/credential-assignment/key-pattern/HTML text before acceptance/export. This guard is not a universal DLP guarantee. Exporting website text in a future digest version requires separate privacy/injection review, not reuse of persistence sanitation.

## Calls, failure and audit

Explorer: one call, 20 seconds, requested output cap 768 tokens. Breaker: one call, 20 seconds, 1024 tokens. Whole tribunal: 45 seconds, no semantic retries. Breaker skips with no accepted claims. No exportable evidence skips both roles. Responses must be <=24 KiB UTF-8 **before JSON parsing**; object payload serialization rejects getters, toJSON, symbols, exotic/cyclic/sparse data, excessive nesting/cardinality and non-JSON values. Failure envelopes and usage metadata are separately checked. Input/output usage must be bounded integers or unavailable null; output usage above the role cap rejects the response.

`UntrustedProviderResult` contains unknown payload with optional bounded adapter-reported usage, or a categorized configuration/unavailable/transport/timeout/abort failure. Missing usage remains null, never fabricated zero. There is no tokenizer or real provider in this stage: token limits are request constraints plus reported-usage validation, not independent billing/token attestation. Future trusted adapters must enforce server-side token/transport-body limits and cancellation. Host timeouts stop acceptance and signal abort; late promises cannot mutate state. An adapter ignoring abort may continue its own work. In-process adapters are trusted host code, not a JavaScript/process sandbox; only model response data is untrusted. No adapter receives mutation callbacks or raw reports.

One TribunalRun v1 overlay contains two bounded AgentRun audit records, ordered Explorer then Breaker, including skipped/failure records. Host identities, scan/role/provider/model, start/finish/monotonic elapsed time, schema versions/structural JSON-schema hashes, request/response hashes, status, usage, accepted IDs, exact recognizable proposal rejection counts, explicit rejectedCountKnown (false for undecodable output), bounded codes and call/time/token budgets are retained. JSON-schema hashes identify structure; versioned host policy covers refinements/reference semantics. Invalid/oversized raw outputs, raw provider exceptions, credentials, chain-of-thought and reasoning traces are not retained. Oversized/unserializable responses have no response hash; bounded malformed JSON is hashed without persistence.

A valid empty Breaker response completes with no challenges; this is not a verdict or agreement. An empty Explorer response has no valid output and skips Breaker. Completion, partial rejection, no valid output, configuration/provider/transport failure, timeout, abort, malformed output, schema failure, limit exceeded and skipped are distinct. An authorized Explorer result may survive a later failed/aborted Breaker as a partial/aborted overlay; no half-authorized item or prior report mutation is published. The complete next report is schema-validated before return. Callers receive a new immutable report; there is no storage side effect.

## Report v2 migration

ScanReport v2 requires claim scope/falsifier/createdAt/status, challenge category/scanId/createdAt/provenance and `tribunalRuns` (zero or one). Deterministic producers and demo/live fixtures explicitly populate the new fields. Deterministic claims can retain up to 96 references and longer bounded statements; agent claims remain <=6 references/480 characters. The duplicate-title HTTP rule already cites eight pages, which must not be silently truncated to the model budget.

Base findings/verdicts/claims and the demo's legacy narrative agentRuns retain their existing meanings. New activity exists only in `tribunalRuns[].agentRuns`; the overlay adds no findings/verdicts or UI behavior. Deterministic HTTP report validation still prohibits invented base agent activity. V1 persisted local reports fail validation and must be recollected; required scope/authority fields are not invented by an automatic compatibility reader. The local report store is ephemeral, not a deployment migration system.

OBSERVED is directly collected; DERIVED is deterministic calculation; INFERRED is hypothesis; SIMULATED is illustration. Fixture source alone does not imply SIMULATED: owned browser fixture observations can be real. The hand-authored demo stays an explicitly labeled example, with no tribunal run.

Skeptic is implemented only as the separate offline review above. Reproducer Stage 16A implements offline planning and host authorization with injected fake execution only; its results are SIMULATED/test-only and establish no real reproduction. Real controlled-fixture Reproducer execution, experiment generation, Judge, and tribunal verdict generation remain deferred. Stage 14C has offline real-adapter code; its real-provider acceptance remains pending. Existing deterministic HTTP findings confirm only predicates over returned responses/HTML, not reproduction, causality or AI consensus. Public Chromium launch remains fail-closed with ISOLATION_UNAVAILABLE. Stage 14C must separately review provider configuration, transport, token enforcement, cancellation and admission; Stage 14B grants no network, browser, shell, filesystem or action authority to models.
