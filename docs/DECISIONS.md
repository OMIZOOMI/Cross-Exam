# Decision log

Decisions 001–010 were accepted for the foundation on 2026-09-30; later decisions carry their own dates. Revisit with a concrete product need.

| ID | Decision | Reason and tradeoff |
| --- | --- | --- |
| 001 | TypeScript end-to-end, Zod at boundaries | One domain vocabulary across web, scanner, engine, and agents. Runtime checks remain necessary; TS types cannot validate external data. Pin TS 5.9 to the stable toolchain instead of adopting a new compiler major in week one. |
| 002 | pnpm monorepo with private source packages | Shared contracts stay in sync while worker/web boundaries remain clear. No task-runner framework or package publication needed for five small packages. Use pnpm 11's explicit `allowBuilds` for esbuild; exact dependencies + lockfile. |
| 003 | Next.js App Router + React | Provides routing, server-rendered entry pages, production builds, and local hosting in one app. Client state handles the fixture views. Revisit server/job adapters when real scanning works. |
| 004 | Playwright + Chromium | Deterministic browser automation and repeatable UI checks; later enables technical collection. It is installed only for product browser tests now. Browser downloads and future worker isolation have costs. |
| 005 | Deployment-independent local foundation | No database, Redis, queue service, AWS, account, paid API, or model SDK. Learn from a working deterministic pipeline before selecting persistence/hosting. No deployment in this task. |
| 006 | Separate fixture module + explicit source + runtime reference checks | Prevents accidental fixture/live mixing and dangling evidence. Reserved `acme.example` avoids implying an audit of a real business. No “scan” button secretly redirects to fake results. |
| 007 | Structured adversarial records and provider-neutral roles | Supports different models without forwarding large chat transcripts. Real validation, orchestration, experiment authorization, budgets, and providers are deferred. No invented runtime AI reasoning. |
| 008 | Tailwind foundation, small semantic primitives, CSS tokens | Small semantic primitives without a large UI kit. The original charcoal/olive styling is superseded by decision 011. Buttons, inputs, badges, sections, and native disclosure behavior need no additional primitive library. No Framer Motion: modest CSS feedback is sufficient now and respects reduced motion. |
| 009 | React Flow + Recharts, loaded on demand | Real interactive map and readable timings, with a route table/select fallback. Avoid deploying chart/graph code in the landing component. No opaque synthetic health score. |
| 010 | Biome, Vitest, Playwright | Fast format/lint, meaningful data-boundary/unit tests, and desktop/mobile user-flow validation. CSS descending-specificity lint is disabled because independently scoped class descendants produce false positives; accessibility lint remains enabled. |
| 011 | Editorial investigation identity (2026-10-01) | Warm neutral surfaces, Georgia headings, sans-serif product copy, semantic status colors, open report sections, and compact evidence rows. Preserve fixture boundaries and domain contracts; refactor only the web presentation. See `DESIGN.md`. |
| 012 | Strict V1 destination policy (2026-10-01) | HTTP/HTTPS only; ports 80/443 only; reject all direct IP targets, userinfo, raw controls/whitespace, ambiguous authorities, and local/reserved names. WHATWG parsing normalizes IDNA and unusual IPv4 spellings before checking. A syntax decision is never connection authorization. |
| 013 | All-answer DNS validation and pinned native HTTP transport (2026-10-01) | Resolve A and AAAA per hop; reject any unsafe answer or ambiguous family failure. Use an explicit one-use Node HTTP(S) agent that connects to one validated literal IP, retains the DNS hostname for Host/SNI/certificate checks, and hands the verified socket to HTTP only after connection checks. No second DNS lookup, environment proxy, socket reuse, arbitrary headers, or automatic redirects. Prefer native Node over an additional Undici dependency because this narrow GET/HEAD boundary needs no fetch compatibility. |
| 014 | Conservative IP policy and browser isolation boundary (2026-10-01) | Use pinned ipaddr.js for parsing/CIDR arithmetic, explicit IANA special-use ranges plus cloud platform addresses and the scanner’s own public interfaces; IPv6 permits ordinary 2000::/3 global unicast only. Deny special-purpose exceptions even when globally reachable. Chromium remains disabled until a separate enforcing proxy plus network isolation prevents direct TCP/UDP and proxy bypass. Interception alone is insufficient. |
| 015 | Bounded stateless HTTP observations (2026-10-01) | GET/HEAD only, fixed headers, no cookies/auth/body/custom transport, no compression decoding, 5 redirects, HTTPS downgrade denial, 10-second default/30-second maximum whole-operation deadline, 1 MiB body and 16 KiB header cap. No automatic fallback or retry; prefer a denied/unavailable observation to an ambiguous destination. Browser-wide and job-wide budgets remain future work. |

## Real HTTP investigation milestone — 2026-10-01

| ID | Decision | Reason and tradeoff |
| --- | --- | --- |
| 016 | Deliver deterministic HTTP/HTML collection before browser instrumentation | A useful real report requires no Chromium, model, or simulated measurements. Cheerio 1.2.0's slim parser reads supplied bytes only; no script execution, resource downloads, or raw HTML retention. Observations are OBSERVED; rule matches are DERIVED, attributed to “Deterministic rule,” with no invented agents or reproduction. A confirmed rule match is not independently reproduced causation. |
| 017 | Eight page attempts, depth two, sequential collection, final-origin scope | Preserve the existing 1 MiB response ceiling; metadata is 256 KiB each; 8-second request and 45-second scan deadlines; ten safe-request operations including robots/sitemap. At most five redirects per operation. Byte accounting records completed bodies (8.5 MiB maximum), not all wire traffic. Navigation ignores queries, downloads, action/account/API paths, fragments, and sibling origins. Limits live in `apps/scanner/src/limits.ts`. |
| 018 | Restriction-only redirect callback inside the existing egress gate | The scanner may narrow allowable redirect destinations, never authorize an otherwise denied destination. Full URL/redirect checks precede the callback, which must synchronously return true; DNS/IP pinning still runs for every approved hop. Initial public redirects establish the final entry origin; subsequent page redirects must remain on that origin and obey crawl/robots policy. Metadata redirects must retain their conventional path. |
| 019 | Compact metadata, conservative discovery, and narrow findings | Attempt only conventional robots.txt and sitemap.xml through safeRequest. Unknown robots policy stops extra pages; conservative Disallow prefixes apply without Allow exceptions. Sitemap indexes/entities are not followed; at most 50 URL hints. Missing headers are informational observations, canonical checks validate declared syntax only, mixed content is a declaration rather than browser behavior, and large HTML is not a performance score. |
| 020 | Local Node execution and bounded file persistence | A same-origin loopback-only POST adapter runs one scan at a time, with six starts/minute. It compares exact Origin against an allowlisted original Host because Next normalizes loopback request URLs. Reports use UUIDs, schema validation, atomic private files, 4 MiB/report, 20 retained reports, and 24-hour read expiry. Random IDs are not authentication. This intentionally is not a public multi-tenant job service. Blocking metadata waits for the report lookup so missing reports return HTTP 404. |
| 021 | Live report branches reuse the approved editorial presentation | The demo module stays synthetic and unchanged. Live views use real pages, graph edges, evidence, timings, rule matches, recommendations, and JSON export. Browser measurements, agent activity, fake experiment chains, and fixture-only solution outcomes are omitted from live reports. |
| 022 | Git synchronization is part of completion | After passing all checks and reviewing secrets/scope, update docs, commit descriptively and push to origin/main. Fetch first, preserve unrelated history, never force-push without explicit instruction, and report authentication blockers. See AGENTS.md and AI_WORKFLOW.md. |
| 023 | Non-MITM browser egress proxy, shared destination policy | Reuse URL/all-answer DNS/IP validation and pinned HTTP transport. Strict CONNECT authorities pin TCP to an approved peer; Chromium retains end-to-end TLS validation. HTTP redirects are checked at proxy level; encrypted paths/methods/WSS cannot be inspected. Never present an application proxy as an OS firewall. |
| 024 | Fixture-only browser worker until externally enforced isolation is verified | Chromium manual proxy with `<-loopback>`, fresh context, service-worker/WebSocket restrictions and workload bounds is defense in depth. No Docker/Podman is available on this macOS host; no privileged host networking changes. An unavailable isolation backend fails closed rather than accepting a caller's boolean attestation. Public form remains deterministic HTTP only. |
| 025 | Verify proxy behavior with closed fixtures, not real private probes | On Playwright 1.63.0 / Chromium 153.0.8010.12, real browser traffic reaches the proxy, loopback IPv4/IPv6 sentinels remain untouched, proxy outage has no direct fallback, and self-signed TLS is rejected end-to-end. Private-range literals are proxy request data; fake resolver answers never select real infrastructure. One local WebRTC/STUN observation is not network-isolation proof. Keep task 9a partial and browser collection blocked. |
